# Empty-board pass-loop diagnosis

The first quick pipeline trained all three eight-match agents successfully, but their frozen greedy policies produced truncated evaluation games. For example, DQN-Random on evaluation seed 8,000,000 and seat 0 reached the 5,000-action bound. No finishing outcome was substituted. The original log and failed CSVs are preserved under `results/quick_pipeline.log` and `results/quick_failed/`.

A targeted reproduction found the learner holding three rank-4 cards with an empty board and two players left. The upstream engine considers both discards and `pass` legal. In a two-player round, one pass immediately declares pizza; with no prior discarder, the next round can again start with the same player. The early greedy policy repeatedly chooses pass, preventing the opponent from acting. This is an interaction between a weak learned policy and the pinned engine’s empty-board passing semantics, not an illegal-action or hidden-information failure.

The final protocol uses a transparent shared policy-choice constraint: when the board is empty and at least one discard is officially legal, passing is excluded from the policy’s choice mask. This applies identically to every learner, random baseline, heuristic baseline and opponent, during both training and evaluation. Bootstrap next-state masks use the same constraint. The environment’s official action catalogue, legality mask and game rules are not changed. The constraint never adds an illegal action, and never replaces an action after execution.

This is a progress restriction, not a claim that empty-board passing is illegal under the upstream rules. It changes the tested policy class and the constrained random baseline. Final results are therefore conditional on this shared restriction. The original failed run is not included in final aggregate performance. Regression tests show that the official mask is left unchanged and a pass-preferring policy completes under the shared progress constraint.
